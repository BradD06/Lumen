# Lumen: дорожная карта

Lumen задуман как аналог Notion, заточенный под учёбу, задачи и заметки. От Notion его отличают четыре вещи:

1. **Читалка книг** любых распространённых форматов прямо внутри приложения.
2. **Выписки и ссылки на цитаты**: выделил фрагмент в книге, и он становится блоком на любой странице, а по ссылке можно вернуться ровно к этому месту в книге.
3. **Виджеты и магазин виджетов**: таймеры, трекеры, прогресс и прочее, что встраивается в страницы.
4. **Кастомизация** приложения и отдельных страниц с помощью тем и виджетов.

Этот документ отвечает на два вопроса: что уже готово и что делаем дальше, **строго по порядку**. Следующий шаг начинаем, только когда закончен предыдущий. У каждого шага есть задача (issue) на GitHub с галочками, по ним видно, что осталось. Подробности о стеке, модели данных и рисках собраны в справочнике в конце.

Чего в Lumen не будет: карточек для запоминания и интервального повторения (flashcards, spaced repetition). Это решение принято, к нему не возвращаемся.

---

## Главное решение о платформах (30.10.2026)

1. **Сначала доводим до конца Mac и iPhone.** Пока они не готовы, другие платформы не начинаем.
2. **Потом синхронизация через Supabase.** Она заменяет iCloud на всех устройствах, включая iPhone. iCloud работает только на устройствах Apple и требует платный аккаунт разработчика, а Supabase работает везде и на старте бесплатен.
3. **Вход в аккаунт:** сначала по почте и через Google. «Вход через Apple» добавляем, когда появится платный аккаунт Apple за $99 в год. Аккаунты пользователей при этом не теряются.
4. **Потом отдельное приложение для ПК (Windows) на C#** с теми же данными через Supabase. Решение от 30.10.2026, вместо веб-версии.

## Что делаем дальше, по порядку

### Часть 1. Доводим Mac и iPhone

#### Шаг 1. Трекер задач ([#16](https://github.com/BradD06/Lumen/issues/16))
- Базы данных в духе Notion: таблица со свойствами (текст, число, выбор, дата, чекбокс, ссылка на страницу).
- Представления «таблица» и «канбан», затем «календарь» и «список». Фильтры, сортировки, группировки.
- Готовый шаблон «Задачи» (статус, срок, приоритет, проект) и экран «Сегодня».
- Напоминания на устройстве (уведомления).
- Задачи можно связать с книгой или страницей: «прочитать главу 3» ведёт прямо в читалку.

#### Шаг 3. Встроенные виджеты и главный экран ([#18](https://github.com/BradD06/Lumen/issues/18))

- Помодоро, привязанный к задаче, и учёт времени учёбы.
- Виджеты на рабочем столе iPhone и Mac (WidgetKit): задачи на сегодня, текущая книга.

#### Шаг 4. Доводка перед бетой ([#19](https://github.com/BradD06/Lumen/issues/19))

- Выделение прямоугольной области на сканах и картинках.
- Общая полировка: скорость на больших страницах, мелкие ошибки, которые накопились.

После этого шага Mac и iPhone версии считаются готовыми.

### Часть 2. Синхронизация и аккаунты

#### Шаг 5. Синхронизация через Supabase ([#20](https://github.com/BradD06/Lumen/issues/20))
- Аккаунт Supabase, таблицы в облачной базе (Postgres) повторяют локальные: страницы, блоки, папки, книги, выделения, время чтения, задачи.
- Вход по почте и через Google. Каждый пользователь видит только свои данные (правила доступа Row Level Security).
- Приложение по-прежнему работает без сети. Изменения копятся в журнале (он уже есть в базе с PR #10) и отправляются, когда появится интернет. Конфликты решаем по правилу «последняя правка побеждает» для каждого поля.
- Файлы книг хранятся в Supabase Storage.
- Код iCloud (CloudKit) убираем, его заменяет Supabase.
- Проверка на двух устройствах и без сети.

#### Шаг 6. Вход через Apple ([#21](https://github.com/BradD06/Lumen/issues/21))
- Делаем, когда появится платный аккаунт разработчика Apple ($99 в год). Тогда же становятся доступны TestFlight и App Store.
- Вход через Apple подключается к уже существующим аккаунтам, данные не теряются.

### Часть 3. Магазин и новые платформы

#### Шаг 7. Магазин виджетов и тем ([#22](https://github.com/BradD06/Lumen/issues/22))
- Язык описания виджетов (JSON), встроенные виджеты переводим на него, чтобы проверить на практике.
- Каталог виджетов и тем хранится в Supabase. Установка, обновление, удаление.
- Платные виджеты и темы по желанию, позже.

#### Шаг 8. Приложение для Windows на C# ([#23](https://github.com/BradD06/Lumen/issues/23))
- Нативная программа для Windows: C#, .NET и WinUI 3. Код Swift перенести нельзя, поэтому интерфейс пишется заново, но устройство данных (страницы, блоки, книги, выделения) остаётся тем же.
- Локальная база SQLite с той же схемой, синхронизация через официальный клиент Supabase для C#: начал на iPhone, продолжил на ПК.
- Книги: EPUB, FB2, DOCX и другие показываем через WebView2 тем же способом, что и на Mac (HTML плюс наш скрипт выделений), PDF через встроенный в Windows движок PDF.
- Порядок внутри шага: сначала заметки и редактор, потом библиотека и задачи, потом читалка.
- Установка через MSIX-пакет или Microsoft Store.

#### Шаг 9. Расширение (по мере сил) ([#24](https://github.com/BradD06/Lumen/issues/24))
- Форматы MOBI/AZW3, DjVu (после решения вопроса с лицензиями).
- Экспорт и импорт: Markdown, PDF, импорт из Notion.
- Формулы и связи между таблицами, граф связей между заметками.
- Социальные функции для чтения: друзья, книжные клубы, обсуждения.

# Справочник

Ниже исходный план проекта: сценарии, стиль, стек, модель данных и риски. Он остаётся в силе, кроме мест, где явно сказано про Supabase.

## 1. Главные сценарии

Всё приложение строится вокруг двух простых входов. Оба доступны с главного экрана одной кнопкой.

**Просто заметка.** Открыл приложение, нажал «+», пишешь. Никаких обязательных папок, шаблонов и настроек: заметка сразу попадает во «Входящие», разложить её по разделам можно потом.

**Заметки по источнику.** Берёшь книгу или любой файл (PDF, EPUB, FB2, DOCX, презентацию, картинку, скан) и пишешь заметки прямо по нему:
- На iPad и Mac источник и заметка открыты **рядом**, в двух колонках. На iPhone заметка выезжает снизу шторкой поверх источника.
- Выделил фрагмент, и он одним жестом попадает в заметку как цитата со ссылкой на точное место. Для сканов и картинок выделяется прямоугольная область.
- У каждого источника есть своя страница: обложка, прогресс, время чтения, все заметки и выписки по нему. Заметок по одному источнику может быть сколько угодно.
- Обычную заметку можно в любой момент привязать к источнику, и наоборот.

Источник это любой файл, который можно открыть в приложении. Книга лишь самый частый случай.

## 2. Визуальный стиль

Референсы лежат в [`docs/design/references`](design/references). Что из них берём:

- **Тёмная тема по умолчанию** с тёплыми закатными градиентами (персиковый, оранжевый, сливовый, фиолетовый) и мягкими тенями.
- **Атмосферные фоны**: иллюстрации и пейзажи как обложки страниц и фон рабочего пространства. Тема задаёт не только цвета, но и фоновую картинку.
- **Дашборд из карточек-виджетов** со скруглёнными углами: числа, кольца прогресса, графики, таймеры, ползунки. Главный экран и любая страница собираются из таких карточек.
- **Экран книги как дашборд** (референс 03): обложка и название, карточки «Прогресс» (страница из всех), «Время чтения», «Серия дней подряд», список книг в сайдбаре. Цветные яркие карточки на тёмном фоне хорошо выделяют главное.
- Плотная, но аккуратная сетка: крупные цифры, мелкие подписи, много воздуха вокруг карточек.

Социальные функции из референса 03 (друзья, рейтинг, обсуждения книги) в первую версию не входят, это кандидат на поздний этап, когда уже будет Supabase.

## 4. Архитектура

Принцип **local-first**: всё хранится и работает на устройстве без сети, синхронизация это надстройка.

Код делится на локальные Swift-пакеты, чтобы модули собирались и тестировались отдельно:

```
Lumen (app target: iOS + macOS)
├── Packages/
│   ├── LumenCore        модели, идентификаторы, общие протоколы
│   ├── LumenStorage     GRDB: схема, миграции, репозитории, поиск FTS5
│   ├── LumenEditor      блочный редактор: блоки, текст, slash-меню, drag&drop
│   ├── LumenDatabases   таблицы Notion: свойства, представления, фильтры
│   ├── LumenReader      читалка: Readium, PDFKit, конвертеры форматов, выделения
│   ├── LumenWidgets     движок виджетов, встроенные виджеты, DSL для магазина
│   ├── LumenThemes      дизайн-токены, темы, применение к страницам
│   └── LumenSync        синхронизация с Supabase (сейчас там заготовка под iCloud)
└── LumenWidgetKit       расширение для виджетов главного экрана
```

Внутри фич используется связка **View → ViewModel (`@Observable`) → Repository → GRDB**. TCA и другие тяжёлые фреймворки не нужны: на старте важнее скорость, чем строгая архитектура.

**Навигация:** `NavigationSplitView` (сайдбар с деревом страниц, контент, инспектор) на iPad и Mac, стек на iPhone.

**Ссылки:** схема `lumen://` для всего, на что можно сослаться: страница, блок, источник, выделение. На ней же строятся обратные ссылки (backlinks).

## 5. Модель данных

Все сущности имеют `id: UUID`, `createdAt`, `updatedAt` и `deletedAt` (мягкое удаление нужно для корзины и синхронизации).

### Страницы и блоки

- **Page**: `parentId?`, `title`, `icon`, `cover`, `themeId?`, `sourceId?`, `isFavorite`, `sortKey`.
  Страницы образуют дерево. Строка таблицы (database row) тоже является страницей. Страница без родителя попадает во «Входящие». Если задан `sourceId`, это заметка по источнику.
- **Block**: `pageId`, `parentBlockId?`, `type`, `content` (JSON), `sortKey`.
  - Типы на старте: параграф, заголовки H1–H3, списки (маркированный, нумерованный, чекбокс), цитата, код, разделитель, toggle, callout, изображение, файл, ссылка на страницу, **выписка из источника**, **виджет**, встроенная таблица.
  - Текст хранится как массив фрагментов с атрибутами (жирный, курсив, ссылка, упоминание), не как HTML.
  - Порядок блоков задаётся **дробным индексом** (`sortKey` строкой), чтобы вставка между блоками не требовала перенумерации и не конфликтовала при синхронизации.
- **Link**: `sourceBlockId`, `targetType`, `targetId`. Индекс всех ссылок для backlinks и графа связей.

### Базы данных (таблицы Notion)

- **Database**: `pageId` (страница-контейнер), `title`.
- **Property**: `databaseId`, `name`, `type` (текст, число, выбор, мультивыбор, дата, чекбокс, ссылка на страницу, формула позже), `config` (JSON).
- **PropertyValue**: `rowPageId`, `propertyId`, `value` (JSON).
- **View**: `databaseId`, `type` (таблица, канбан, календарь, список, галерея), `filters`, `sorts`, `groupBy` (JSON).

Задачи это шаблон базы данных со свойствами «Статус», «Срок», «Приоритет», «Проект». Отдельной сущности для задач не нужно, но в приложении будет готовый шаблон и экран «Сегодня».

### Источники и выписки

- **Source**: `kind` (книга, документ, изображение), `title`, `author?`, `format`, `file` (копируется в контейнер приложения), `cover`, `progress` (Locator), `lastOpenedAt`.
- **ReadingSession**: `sourceId`, `startedAt`, `duration`. Из них считаются время чтения и серия дней подряд для экрана книги.
- **Highlight**: `sourceId`, `locator` (JSON в формате Readium: `href`, `progression`, `text.before/highlight/after`), `color`, `note`.
  Текст до и после выделения хранится, чтобы найти цитату заново, даже если вёрстка изменилась. Для сканов и картинок вместо текста хранится прямоугольник на странице.
- **Блок «выписка»** хранит `highlightId`. На странице показывается текст цитаты, автор и книга, а нажатие открывает читалку ровно на этом месте (`lumen://source/<id>/highlight/<id>`).
- У каждого источника есть своя страница-дашборд: обложка, прогресс, время чтения, все привязанные заметки и выписки.

### Темы и виджеты

- **Theme**: набор дизайн-токенов (цвета, шрифты, радиусы, отступы, фон) в JSON. Применяется ко всему приложению или к одной странице.
- **WidgetDefinition**: `id`, `version`, `source` (встроенный или из магазина), `manifest` (JSON).
- **WidgetInstance**: `blockId`, `definitionId`, `config`, `state` (JSON).

## 6. Виджеты и магазин: важное ограничение

Правила App Store (п. 2.5.2) запрещают загружать и исполнять код, который меняет функциональность приложения. Поэтому виджеты из магазина будут **декларативными**: JSON-манифест описывает разметку из готовых нативных компонентов (текст, число, прогресс, кнопка, список, график, таймер), источники данных (свойство страницы, запрос к базе, своё состояние) и простые действия. Приложение отрисовывает это нативно.

Порядок работ:
1. Сначала 8–10 встроенных виджетов, написанных на SwiftUI: помодоро-таймер, прогресс-бар по задачам, трекер привычек, обратный отсчёт до экзамена, календарь, текущая книга, цитата дня.
2. Затем по их опыту проектируется DSL, и встроенные виджеты переписываются на него, чтобы проверить его на практике.
3. Только после этого магазин: каталог (хранится в Supabase), установка, обновление версий. Публикация виджетов сообществом и монетизация идут ещё позже.

Темы распространяются тем же каталогом, что и виджеты.

## 7. Риски и решения

| Риск | Что делаем |
|---|---|
| Блочный редактор занимает больше времени, чем ожидается | Начинаем с простой реализации, ограничиваем число типов блоков в MVP, не пытаемся повторить Notion один в один |
| Лицензии: DjVuLibre распространяется под GPL, что несовместимо с App Store | DjVu откладываем; варианты: конвертация на стороне сервера, отказ от формата или поиск коммерческой библиотеки |
| Правила App Store запрещают загружаемый исполняемый код | Виджеты из магазина только декларативные (раздел 6) |
| Конфликты при синхронизации через Supabase | Дробные индексы для порядка, мягкое удаление, слияние на уровне полей; CRDT для текста только при реальной необходимости |
| Цитата «теряется» при смене вёрстки книги | Locator хранит текст до и после выделения, по нему цитата находится заново |
| Производительность больших страниц и таблиц | Ленивые списки, пагинация запросов GRDB, профилирование в Instruments с самого начала |
