# Lumen: план разработки (первая версия на Swift)

Lumen задуман как аналог Notion, заточенный под учёбу, задачи и заметки. От Notion его отличают четыре вещи:

1. **Читалка книг** любых распространённых форматов прямо внутри приложения.
2. **Выписки и ссылки на цитаты**: выделил фрагмент в книге, и он становится блоком на любой странице, а по ссылке можно вернуться ровно к этому месту в книге.
3. **Виджеты и магазин виджетов**: таймеры, трекеры, прогресс и прочее, что встраивается в страницы.
4. **Кастомизация** приложения и отдельных страниц с помощью тем и виджетов.

Первая версия делается нативной под Apple: iPhone, iPad и Mac из одной кодовой базы на SwiftUI.

---

## 1. Стек

| Область | Выбор | Почему |
|---|---|---|
| Язык | Swift 6 (strict concurrency) | Современный стандарт, меньше гонок данных |
| UI | SwiftUI, мультиплатформенный таргет (iOS/iPadOS 18+, macOS 15+) | Один код на три платформы. UIKit/AppKit точечно, где SwiftUI не хватает |
| Хранилище | SQLite через [GRDB](https://github.com/groue/GRDB.swift) | Полный контроль над схемой и миграциями, полнотекстовый поиск FTS5, быстрые запросы для таблиц и деревьев страниц. SwiftData проще на старте, но слабее в поиске, сортировке блоков и синхронизации |
| Синхронизация | iCloud через `CKSyncEngine` (позже) | Бесплатно для пользователя и разработчика, работает с любым локальным хранилищем. Свой сервер можно добавить потом, когда понадобятся веб и Android |
| Редактор текста | TextKit 2 (`UITextView` / `NSTextView` в обёртке) | Стандартный `TextEditor` не даёт нужного контроля над форматированием, slash-меню и markdown-сокращениями |
| Книги: EPUB, PDF, комиксы | [Readium Swift Toolkit](https://github.com/readium/swift-toolkit) + PDFKit | Readium даёт рендеринг EPUB, CBZ и PDF и, главное, модель `Locator` для точных ссылок на место в книге |
| Книги: FB2, TXT, DOCX и другие | Свои конвертеры в HTML/EPUB-представление | FB2 это XML, его несложно разобрать самим |
| Книги: MOBI/AZW3, DjVu | libmobi (LGPL), DjVuLibre (GPL) | Отложены на поздний этап из-за лицензий (см. риски) |
| Виджеты на главном экране | WidgetKit | Задачи на сегодня, текущая книга, цитата дня |
| Тесты | Swift Testing + XCTest для UI | |
| Сборка и CI | Xcode 26, Swift Package Manager, GitHub Actions (macOS runner) | |

Внешних зависимостей минимум: GRDB и Readium. Остальное на стандартных фреймворках Apple.

## 2. Архитектура

Принцип **local-first**: всё хранится и работает на устройстве без сети, синхронизация это надстройка.

Код делится на локальные Swift-пакеты, чтобы модули собирались и тестировались отдельно:

```
Lumen (app target: iOS + macOS)
├── Packages/
│   ├── LumenCore        модели, идентификаторы, общие протоколы
│   ├── LumenStorage     GRDB: схема, миграции, репозитории, поиск FTS5
│   ├── LumenEditor      блочный редактор: блоки, текст, slash-меню, drag&drop
│   ├── LumenDatabases   таблицы Notion: свойства, представления, фильтры
│   ├── LumenReader      читалка: Readium, PDFKit, конвертеры форматов, выделения
│   ├── LumenWidgets     движок виджетов, встроенные виджеты, DSL для магазина
│   ├── LumenThemes      дизайн-токены, темы, применение к страницам
│   └── LumenSync        CKSyncEngine (на этапе синхронизации)
└── LumenWidgetKit       расширение для виджетов главного экрана
```

Внутри фич используется связка **View → ViewModel (`@Observable`) → Repository → GRDB**. TCA и другие тяжёлые фреймворки не нужны: на старте важнее скорость, чем строгая архитектура.

**Навигация:** `NavigationSplitView` (сайдбар с деревом страниц, контент, инспектор) на iPad и Mac, стек на iPhone.

**Ссылки:** схема `lumen://` для всего, на что можно сослаться: страница, блок, книга, выделение. На ней же строятся обратные ссылки (backlinks).

## 3. Модель данных

Все сущности имеют `id: UUID`, `createdAt`, `updatedAt` и `deletedAt` (мягкое удаление нужно для корзины и синхронизации).

### Страницы и блоки

- **Page**: `parentId?`, `title`, `icon`, `cover`, `themeId?`, `isFavorite`, `sortKey`.
  Страницы образуют дерево. Строка таблицы (database row) тоже является страницей.
- **Block**: `pageId`, `parentBlockId?`, `type`, `content` (JSON), `sortKey`.
  - Типы на старте: параграф, заголовки H1–H3, списки (маркированный, нумерованный, чекбокс), цитата, код, разделитель, toggle, callout, изображение, файл, ссылка на страницу, **выписка из книги**, **виджет**, встроенная таблица.
  - Текст хранится как массив фрагментов с атрибутами (жирный, курсив, ссылка, упоминание), не как HTML.
  - Порядок блоков задаётся **дробным индексом** (`sortKey` строкой), чтобы вставка между блоками не требовала перенумерации и не конфликтовала при синхронизации.
- **Link**: `sourceBlockId`, `targetType`, `targetId`. Индекс всех ссылок для backlinks и графа связей.

### Базы данных (таблицы Notion)

- **Database**: `pageId` (страница-контейнер), `title`.
- **Property**: `databaseId`, `name`, `type` (текст, число, выбор, мультивыбор, дата, чекбокс, ссылка на страницу, формула позже), `config` (JSON).
- **PropertyValue**: `rowPageId`, `propertyId`, `value` (JSON).
- **View**: `databaseId`, `type` (таблица, канбан, календарь, список, галерея), `filters`, `sorts`, `groupBy` (JSON).

Задачи это шаблон базы данных со свойствами «Статус», «Срок», «Приоритет», «Проект». Отдельной сущности для задач не нужно, но в приложении будет готовый шаблон и экран «Сегодня».

### Книги и выписки

- **Book**: `title`, `author`, `format`, `fileBookmark` (файл копируется в контейнер приложения), `cover`, `progress` (Locator), `lastOpenedAt`.
- **Highlight**: `bookId`, `locator` (JSON в формате Readium: `href`, `progression`, `text.before/highlight/after`), `color`, `note`.
  Текст до и после выделения хранится, чтобы найти цитату заново, даже если вёрстка изменилась.
- **Блок «выписка»** хранит `highlightId`. На странице показывается текст цитаты, автор и книга, а нажатие открывает читалку ровно на этом месте (`lumen://book/<id>/highlight/<id>`).
- Для каждой книги автоматически собирается страница «Выписки»: все выделения с заметками, которую можно редактировать как обычную страницу.

### Темы и виджеты

- **Theme**: набор дизайн-токенов (цвета, шрифты, радиусы, отступы, фон) в JSON. Применяется ко всему приложению или к одной странице.
- **WidgetDefinition**: `id`, `version`, `source` (встроенный или из магазина), `manifest` (JSON).
- **WidgetInstance**: `blockId`, `definitionId`, `config`, `state` (JSON).

## 4. Виджеты и магазин: важное ограничение

Правила App Store (п. 2.5.2) запрещают загружать и исполнять код, который меняет функциональность приложения. Поэтому виджеты из магазина будут **декларативными**: JSON-манифест описывает разметку из готовых нативных компонентов (текст, число, прогресс, кнопка, список, график, таймер), источники данных (свойство страницы, запрос к базе, своё состояние) и простые действия. Приложение отрисовывает это нативно.

Порядок работ:
1. Сначала 8–10 встроенных виджетов, написанных на SwiftUI: помодоро-таймер, прогресс-бар по задачам, трекер привычек, обратный отсчёт до экзамена, календарь, текущая книга, цитата дня.
2. Затем по их опыту проектируется DSL, и встроенные виджеты переписываются на него, чтобы проверить его на практике.
3. Только после этого магазин: каталог (на старте статический JSON в репозитории или на CDN), установка, обновление версий. Публикация виджетов сообществом и монетизация идут ещё позже.

Темы распространяются тем же каталогом, что и виджеты.

## 5. Этапы

Оценки даны для одного разработчика, работающего с ИИ-помощником, и довольно грубые.

### Этап 0. Подготовка (1 неделя)
- Xcode-проект с мультиплатформенным таргетом, структура пакетов, SwiftLint/SwiftFormat.
- GitHub Actions: сборка и тесты на каждый PR.
- `LumenStorage`: подключение GRDB, первая миграция, тестовая база.

### Этап 1. Страницы и редактор (4–6 недель), ядро MVP
- Сайдбар с деревом страниц: создать, переименовать, переместить, удалить в корзину, избранное.
- Блочный редактор: базовые типы блоков, markdown-сокращения (`#`, `-`, `[]`, `>`), slash-меню `/`, перетаскивание блоков, отмена и повтор.
- Упоминания страниц через `@` и `[[`, обратные ссылки внизу страницы.
- Полнотекстовый поиск по всем страницам (FTS5), быстрый переход `⌘K`.
- Иконки и обложки страниц.

**Самая сложная часть проекта.** Редактор стоит начинать с простого (каждый блок как отдельное текстовое поле в `List`/`LazyVStack`) и усложнять только по необходимости.

### Этап 2. Базы данных и задачи (3–4 недели)
- Таблица со свойствами, представления «таблица» и «канбан», затем «календарь» и «список».
- Фильтры, сортировки, группировки.
- Шаблон «Задачи», экран «Сегодня», локальные напоминания (UserNotifications).
- Виджет «Задачи на сегодня» для главного экрана (WidgetKit).

### Этап 3. Читалка и выписки (4–5 недель)
- Библиотека книг: импорт из «Файлов», через «Поделиться» и перетаскиванием на Mac.
- Чтение EPUB, PDF, TXT, FB2 и CBZ. Настройки шрифта, размера, темы, режимы прокрутки и постраничный.
- Выделение текста цветом, заметки к выделениям, сохранение прогресса.
- **Выписки:** вставка цитаты на любую страницу как блок, переход из блока в книгу на нужное место, автоматическая страница «Выписки» для каждой книги.

**Здесь заканчивается MVP**: этапы 0–3 дают приложение, которым можно реально пользоваться для учёбы, и в котором уже есть главная изюминка. После него стоит выпустить TestFlight-бету.

### Этап 4. Темы и встроенные виджеты (3–4 недели)
- Система дизайн-токенов, 5–6 готовых тем (включая тёмные), редактор своей темы.
- Тема на уровне страницы: фон, шрифт, акцентный цвет.
- 8–10 встроенных виджетов как блоков на странице (список в разделе 4).
- Помодоро с привязкой к задаче и учёт времени учёбы.

### Этап 5. Синхронизация через iCloud (3–4 недели)
- `CKSyncEngine`: отправка изменений, получение, разрешение конфликтов (последняя запись побеждает на уровне поля, для текста блоков позже можно перейти на CRDT).
- Синхронизация файлов книг через CloudKit assets.
- Проверка на двух устройствах и офлайн-сценариях.

После этого этапа можно выходить в App Store с версией 1.0.

### Этап 6. Магазин виджетов и тем (4–6 недель)
- DSL для декларативных виджетов, перенос встроенных виджетов на него.
- Каталог, установка, обновление, удаление. Платные виджеты и темы через StoreKit 2 по желанию.

### Этап 7. Расширение (по мере сил)
- Форматы MOBI/AZW3, DjVu, DOCX (после решения вопроса с лицензиями).
- Экспорт и импорт: Markdown, PDF, импорт из Notion.
- Вложенные базы данных, формулы, связи между таблицами.
- Граф связей между заметками.
- Свой бэкенд для веб-версии, Android и совместной работы.

## 6. Риски и решения

| Риск | Что делаем |
|---|---|
| Блочный редактор занимает больше времени, чем ожидается | Начинаем с простой реализации, ограничиваем число типов блоков в MVP, не пытаемся повторить Notion один в один |
| Лицензии: DjVuLibre распространяется под GPL, что несовместимо с App Store | DjVu откладываем; варианты: конвертация на стороне сервера, отказ от формата или поиск коммерческой библиотеки |
| Правила App Store запрещают загружаемый исполняемый код | Виджеты из магазина только декларативные (раздел 4) |
| Конфликты при синхронизации | Дробные индексы для порядка, мягкое удаление, слияние на уровне полей; CRDT для текста только при реальной необходимости |
| Цитата «теряется» при смене вёрстки книги | Locator хранит текст до и после выделения, по нему цитата находится заново |
| Производительность больших страниц и таблиц | Ленивые списки, пагинация запросов GRDB, профилирование в Instruments с этапа 1 |

## 7. Ближайшие шаги

1. Создать Xcode-проект и структуру пакетов (этап 0).
2. Описать схему базы для страниц и блоков, написать первые миграции и тесты.
3. Сделать прототип редактора на 3–4 типах блоков, чтобы проверить подход до того, как строить на нём всё остальное.
