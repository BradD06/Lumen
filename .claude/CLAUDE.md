# Lumen: notes for coding agents

Read this first. It tells you where things live and which rules the owner set, so you don't have to re-read the whole codebase.

Lumen is a native notes app for Mac, iPhone and iPad (Swift 6, SwiftUI, iOS 18+ / macOS 15+): Notion-like block pages, a reader for almost any book format with excerpts that link back to the exact place, Goodnotes-like handwriting, task databases, and one look: «Остров» (calm flat background, white / graphite sheets, a glass island with the rooms at the bottom, one violet accent; light and dark theme, «Как в системе» by default). The owner approved it on 2026-11-20 and it replaced «Кабинет» (dark green and brass library); the older themes (Закат, Бумага, Монохром, Дзен, Кабинет) stay removed. Build only on «Остров»; the mockup is `/mnt/project-files/design/lumen-ostrov/Остров-2.html` when the project files are mounted. The plan, in Russian, is `docs/ROADMAP.md` (one GitHub issue per step, done in order). The app UI is in Russian.

## Build and test

- `make open`: runs `xcodegen generate` and opens `Lumen.xcodeproj`. The Xcode project and `App/Info.plist` are generated from `project.yml` and are not in git, so edit `project.yml`, never the project file.
- `make test` = `swift test --package-path Packages/LumenKit` (Swift Testing, `@Test` / `#expect`).
- Signing: `Config/Signing.xcconfig` includes the gitignored `Config/Local.xcconfig`, which holds the owner's `DEVELOPMENT_TEAM`. Bundle id is `io.github.bradd06.lumen`.
- CI (`.github/workflows/ci.yml`, macOS 15 runners) runs on every PR: package tests, app build for iOS Simulator and macOS, and macOS UI tests (`UITests/`, target `LumenAppUITests`). The app launched with `-uiTesting` uses an in-memory database and saves no workspace state.
- **A Linux cloud container has no Swift toolchain**, and swift.org downloads are blocked there. Then CI on the PR is the only compile and test check: push, then read the job logs.
- If `swift test` on the Mac fails to codesign `GRDB_GRDB.bundle` (extended attributes, seen when the project lived in `~/Desktop`), use `swift test --package-path Packages/LumenKit --scratch-path /tmp/lumen-build`.

## Conventions and gotchas

- Code comments, UI strings and most commit messages are in Russian. Keep comments short and about why. Commit messages: one short line on what changed for the user.
- **Migrations are append-only and named** (`"v9: drawings, notebooks"`). Never edit a shipped migration, add a new one at the end. When two branches both add one, keep both and pick a sensible order.
- **A new synced table** needs a `SyncTable` case (in dependency order) and `createSyncTriggers(db, table:)` in its migration. Every change to synced tables is logged to `syncChange` even while sync is off.
- **CloudKit sync stays off** in the default build: never add iCloud entitlements or a container to `project.yml`. It turns on only through `Config/Local.xcconfig` (see README). The default sync is the folder sync (user picks an iCloud Drive folder in «Данные и копии», security-scoped bookmark in `sync.folderBookmark`), which needs no entitlements. The long-term plan adds Supabase.
- **A new synced table** also needs `createSyncClockTriggers(db, table:)` in its migration (folder sync clock). Never loop over `SyncTable.allCases` inside a migration: older migrations run before the new table exists.
- A new `SidebarItem` case needs a title in `ItemTitle` and a branch in `RootView.detail`, and on iPhone in `PhoneRootView`.
- In split screen, toolbars and shortcuts of the inactive pane are hidden via the `isActivePane` environment value. Never switch a view's identity on `isActivePane` (an `if/else` on it rebuilds the whole editor on focus change).
- Links clicked in a note open in the opposite pane when the tab is split (`RootView.openLink(_:from:)`). Excerpts from a book go to the note open beside it (`besidePageId`), otherwise to the book's notes. Book notes live in the book's folder next to the book and are created lazily (`ReaderModel.ensureNotes()`).
- Custom drag types and document types are declared in `project.yml` under `info:`. Don't set `LSSupportsOpeningDocumentsInPlace` (Xcode rejects `NO` for the macOS side).
- In `LumenUI` files that import GRDB, write `ButtonStyleConfiguration`, not `Configuration` (name clash).
- PDF text mode: places are always stored in PDF terms (`SourceLocator.section` = page; in the Text view `textOffset` counts characters from the page start), so highlights, excerpts and the reading place work in both views. `PDFTextIndex` maps pages to chapter offsets; chapter HTML has no whitespace between tags so its character counts match `ReaderScript`'s.
- PDF margins and columns (Original view): `PDFLayoutAnalyzer` renders every page small in the background once (cached in Caches/LumenReader/pdf-layout) to find the content box and a column gap; `PDFLayoutPlan` turns that into crop boxes of one common width, or two pieces per two-column page. `PDFReaderController` then shows pieces, not file pages (the second column comes from a second `PDFDocument` of the same file), and maps everything back: locators, highlights, events and `pageCount` are always in file pages. With pieces it computes its own fit-width scale instead of PDFKit's `autoScales`.
- Tests: use `AppDatabase.inMemory()`. Wait for the editor to save with `model.flush()`, not sleeps. Keep heavy PDF / Core Image rendering out of main-actor tests, it slows the timing-sensitive ones on CI.
- Speed (checked with a resize/scroll benchmark on the owner's data, 2026-11-16): a size or frame that only handlers read (drop delegates, ⌘J, drag) goes into a `GeometryBox` in `@State`, never into plain `@State` or the environment, or every frame of a window resize rebuilds the screen (`RootView` did, and with it the reader). For a layout switch, use `onGeometryChange(for: Bool.self)` so the action fires only when it flips. A view's `init` runs on every parent rebuild: never create heavy objects there or in a model init (`WKWebView`, `PDFView`, `AVPlayer`); make them `lazy` (`ReaderModel.web` / `.pdf`, `PlayerHolder`). Shadows go on the card's shape, not on its content (`readerGlassCard`, `ShapeShadow`). The blurred bookcase is a cached image (`BookcaseImage`). Values that change while scrolling (visible sheet, outline highlight, word count) are read in small child views (`LiveSheetRail`, `LiveOutline`), not in `PageEditorView.body`. On macOS a `LazyVStack` re-renders its whole content on every scroll frame (every small `Text` / `Image` in the rows is redrawn), so note sheets use a plain `VStack` up to `PageEditorView.lazySheetLimit` sheets (`SheetStack`, chosen once per open). To keep opening fast, only the first `SheetLoader.initialSheets` sheets are built at once; the rest are empty A4 paper (`DeferredSheet`) built one by one after open while the page isn't scrolling, or right away when scrolled to, jumped to or focused (`SheetLoader.reveal`). Row hover must not rebuild the row: keep hover state in a small `@Observable` box read only by the view it changes (`RowHover` / `HandleGlyph`), and ignore hover entry while `PageEditorModel.isScrolling` (set from `onScrollPhaseChange`), or every row passing under a still cursor rebuilds mid-scroll. Never use `@AppStorage` in views; use `@Setting` (`Navigation/Setting.swift`, same syntax): SwiftUI on Mac writes the window position to UserDefaults on every move, and `@AppStorage` wakes its view on any write, so dragging the window rebuilt the whole screen 60 times a second. `AppActions` compares only by `owner`, so a `RootView` rebuild doesn't rebuild every screen; keep its closures touching only `@State` and the database.
- Animations: take curves from `LumenMotion` (`LumenThemes/Motion.swift`: `quick` for hover / press, `standard` for panels, tabs, lists, `gentle` for big objects, `screen` for changing the screen in a pane) instead of ad-hoc `.easeOut(...)` / `.snappy`. They are springs, so an interrupted animation continues smoothly, and they turn into a short fade with Reduce Motion. A pane fades between screens by `SidebarItem.screenKey` (`RootView.pane`); UI tests (`-uiTesting`) switch screens without it.
- Colors: never hard-code colors or `.preferredColorScheme(...)` in screens; read `@Environment(\.lumenTheme)`. There is a light and a dark theme, so check both. Paper and cards are `theme.sheet`, quiet fills `cardFill` / `surface2`, hairlines `line`, selected-button fill `accentSoft`. For thin highlights use `theme.contrast.opacity(...)` instead of `.white`; text on an accent fill is `theme.onAccent`.
- Note covers: the editor draws the cover through `Editor/PageCoverBand.swift` (the first sheet overlaps its lower edge; «Ракурс» drags / zooms the picture and picks the band height). The angle is `LumenCore/CoverCrop` stored in `page.coverCrop` (migration v20, `nil` = centred, medium); a new picture resets it but keeps the height. The window takes the open note's cover color through `CoverTint.shared` (set by the editor in the active pane, cleared when it leaves) and `Theme.tinted(by:)`, applied in `LumenThemeHost` unless UserDefaults `appearance.coverTint` is off (Settings → «Обложки», on by default).
- `UserDefaults` keys in use include `workspace.v1`, `reader.*` (appearance, `reader.sidePage.<sourceId>`, `reader.layout` / `reader.layout.<sourceId>` (notes beside or under the book), `reader.pdfZoom.<sourceId>` (locked scale), `reader.pdfZoomFactor.<sourceId>` (free zoom relative to fit width), `reader.pdfMode.<sourceId>`, `reader.pdfCrop.<sourceId>`, `reader.pdfColumns.<sourceId>`) `drawing.recentColors`, `shelf.sort`, `shelf.status`, `shelf.display`, `appearance.mode` (system / light / dark; the old `appearance.scheme` and `appearance.daylight*` are no longer read), `sounds.enabled`, `library.snapToGrid`, `screen.*` (`ScreenOptions`), `sync.folderBookmark`, `reading.dailyGoalMinutes` (daily reading goal, 0 = none), `sync.setupCardHidden` (the Home sync card was dismissed) and `sync.deviceId` (this install's folder name in `Lumen Sync/devices`).
